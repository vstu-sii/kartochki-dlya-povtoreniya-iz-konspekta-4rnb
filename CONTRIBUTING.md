# Как работать с проектом

1. Создать ветку от нужной лабораторной, не коммитить `.env` и пользовательские PDF.
2. Перед commit выполнить unit-тесты, mini-eval и `docker compose -f compose.yml config --quiet`.
3. Изменение prompt/model сопровождается новым eval-артефактом; эталон dataset нельзя менять только ради зелёного CI.
4. Изменение API сначала вносится в `api/openapi.yaml`, затем в backend/AI adapter.
5. Миграции добавляются новым номером и не переписываются после применения.
6. PR одной роли имеет заголовок `Lab3: [Role] — Prototype Deliverables` и перечисляет фактические проверки.
