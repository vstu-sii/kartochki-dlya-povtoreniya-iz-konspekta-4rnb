## Найденные ошибки production до исправления

Два реальных запроса подтвердили `model=gemini-3.5-flash-lite` и `fallback_used=false`, но контракт выполнялся не полностью:

- при `requested_card_count=5` один прогон вернул 4 карточки;
- в ответе генерации отсутствовал `trace_id`;
- поэтому удалось измерить только сценарий `1 генерация + 4 разбора`, а не требуемый `1 + 5`.

Измеренный неполный сценарий использовал 1018 входных и 482 выходных токена. Эквивалент по Standard-тарифу Gemini 3.5 Flash-Lite (`$0.30/1M` input, `$2.50/1M` output):

`1018 / 1 000 000 × 0.30 + 482 / 1 000 000 × 2.50 = $0.0015104`.

Это ниже бюджета Lab1 `$0.04`, но не называется стоимостью полного сценария.

## Исправление

- generation prompt теперь требует **ровно** запрошенное число карточек;
- JSON Schema задаёт одинаковые `minItems` и `maxItems`;
- normalizer отклоняет любое количество, не равное `requested_card_count`;
- модельный `trace_id` сохраняется вместе с idempotency identity без миграции существующей БД;
- новый ответ и idempotent replay возвращают одинаковый модельный `trace_id`;
- версия generation prompt повышена до `cards-v2.2`.

Дополнительно применена уже проверенная интеграционной веткой совместимость геометрического PDF-extractor с Windows, чтобы полный локальный regression gate не терял две формулы.
