## Границы подтверждения

- X-User-ID обязателен для чтения сессии по ID, review, progress, ratings и complete. Review использует только каноническую карточку из БД этой сессии, а не присланный клиентом эталон. При этом заголовок остаётся заявленной клиентом идентичностью, а не серверной аутентификацией: не заявляем полноценную защиту от подмены пользователя.
- Mini safety вызывает тот же guard, который использует backend; HTTP-регрессии дополнительно проверяют подключение валидации к endpoint.
- Общие 128 кейсов не означают browser E2E: модельный и прикладной наборы проверяются раздельно.
- Evals используют оценку токенов, не фактическую стоимость Gemini.
- Внешняя приёмка UC, ручное ревью golden v2 и согласование спринта требуют реальных подтверждений. Назначенные участники не считаются подписавшими протокол.
- Scheduled GitHub Actions начнёт выполняться автоматически только после включения workflow в default branch. Пока доступны push/PR mini; full можно воспроизвести командой из README.
