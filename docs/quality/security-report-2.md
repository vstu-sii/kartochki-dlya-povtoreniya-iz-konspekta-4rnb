# Security report v2 — закрытие и повторный прогон

Команда:

```bash
python tests/security/run_attacks.py --mode after --output artifacts/security/lab4-attacks-after.json
```

## Чем закрыто

- Direct/indirect injection блокируется `backend/guards/policy.py` до вызова модели.
- Текст нормализуется NFKC, удаляются zero-width символы, разделители не обходят правила.
- `lookup_source` сверяет пользователя с владельцем и предоставляет только read-only контракт.
- Запись рейтинга, завершение сессии и доступ к чужой сессии остаются только в application endpoints; LLM не получает таких инструментов.
- Tool timeout ограничен и превращается в явный `tool_status`, а не в бесконечное ожидание.

## Повторный результат

Все 12 сценариев совпадают с ожидаемой политикой: 10 атак блокируются, 2 безопасных контрольных текста проходят. Результат сохраняется в `artifacts/security/lab4-attacks-after.json` и проверяется на каждом PR.

## Принятый риск

Regex/policy gate не заменяет полноценный классификатор и может дать false positive для учебного PDF, который дословно цитирует атаку. Цена принята для MVP: пользователь получает стабильный код `PROMPT_INJECTION_BLOCKED`; спорный документ не отправляется модели. Новые обходы становятся кейсами того же набора.
