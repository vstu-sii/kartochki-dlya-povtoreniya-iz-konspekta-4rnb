# Где врёт baseline: eval-прогон №1

Прогон: `python tests/evals/run_evals.py`. Dataset: 120 исходных + 8 новых случаев Lab 3. Модель: воспроизводимый `deterministic-grounded-v1`; облачный Gemini без ключа не выдаётся за измеренный.

## Фактические цифры

| Метрика | Результат | Продуктовый смысл |
|---|---:|---|
| Schema pass rate | 100% | UI получает ожидаемые поля |
| Grounded-card rate | 100% | Цитата действительно находится на указанной странице |
| Agreement review с эталоном | 90,48% | Порог 85% закрыт; четыре расхождения оставлены для ручного разбора |
| API/DB dataset | 33/33 | Отдельный Delivery-runner вызывает реальные guard-, router- и ORM-функции |
| p95 локального прогона | 1 мс | Характеризует только локальный детерминированный baseline, не облачный API |

Полный набор содержит 128 строк: 95 модельных проверены model runner, 33 прикладных — отдельным API/DB runner. Канонические результаты: [baseline-results.json](https://github.com/vstu-sii/kartochki-dlya-povtoreniya-iz-konspekta-4rnb/blob/lab3-quality-prototype/artifacts/evals/baseline-results.json) и [application-results.json](https://github.com/vstu-sii/kartochki-dlya-povtoreniya-iz-konspekta-4rnb/blob/lab3-quality-prototype/artifacts/evals/application-results.json).

## Типы ошибок с живыми примерами

1. **Краткий верный ответ объявлен частичным.** REV-001: студент передал суть с использованием `RAM`, но baseline не восстановил всю семантическую связь. Боль высокая: студент получает заниженную оценку.
2. **Спорная эталонная разметка.** REV-021, REV-024 и REV-039 содержат почти дословный ожидаемый ответ, но размечены как `partially_correct`; модель ставит `correct`. Эти кейсы нельзя автоматически подгонять — требуется ручное решение Quality/Product.
3. **Повторы карточек на коротком тексте.** GEN-LIVE-001: схема и grounding зелёные, но пять карточек строятся из одного тезиса. Боль средняя: тренировка однообразна.
4. **Технические разрывы UC-03/04 (закрыты 13 октября).** Первый прогон обнаружил отсутствие рейтинга и resume. После исправления Web/Telegram вызывают API, последняя оценка и позиция сессии сохраняются в БД; это проверяет E2E smoke-test.

## Приоритет AI Engineer по боли

1. Вручную пересмотреть четыре оставшихся расхождения, не меняя эталон автоматически.
2. Затем выделять независимые тезисы до генерации, чтобы не создавать дубли.
3. После этого подключать Gemini-прогон и сравнивать его с тем же dataset; средняя цифра без разреза по verdict не принимается.

Терпимо для текущей демонстрации: локальная формулировка вопроса шаблонна. Нетерпимо для следующего спринта: review ниже 85% согласия. PDF с текстовым слоем уже принимается Telegram-адаптером; OCR для сканов остаётся осознанным не-скоупом MVP.
