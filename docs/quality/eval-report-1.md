# Где врёт baseline: eval-прогон №1

Прогон: `python tests/evals/run_evals.py`. Dataset: 120 исходных + 8 новых случаев Lab 3. Модель: воспроизводимый `deterministic-grounded-v1`; облачный Gemini без сохранённого измерительного артефакта не выдаётся за измеренный.

Ручной UX-слой того же спринта: внешний студент Постернак Денис, 15.10.2026 — см. `docs/use-cases/validation-lab3.md`.

## Фактические цифры

| Метрика | Результат | Продуктовый смысл |
|---|---:|---|
| Schema pass rate | 100% | UI получает ожидаемые поля |
| Grounded-card rate | 100% | Цитата действительно находится на указанной странице |
| Agreement review с эталоном | 90,48% | Порог прототипа 85% закрыт на deterministic fallback; четыре расхождения оставлены для ручного разбора |
| API/DB dataset | 33/33 | Delivery-runner вызывает реальные guard-, router- и ORM-функции |

| Оценка токенов | 23 674 входных / 13 275 выходных | Воспроизводимая оценка fallback, не billing Gemini |

Полный набор: 128 строк (95 модельных + 33 прикладных). Канонические результаты: [baseline-results.json](https://github.com/vstu-sii/kartochki-dlya-povtoreniya-iz-konspekta-4rnb/blob/lab3-quality-prototype/artifacts/evals/baseline-results.json), [application-results.json](https://github.com/vstu-sii/kartochki-dlya-povtoreniya-iz-konspekta-4rnb/blob/lab3-quality-prototype/artifacts/evals/application-results.json).

## Типы ошибок с живыми примерами

1. **Краткий верный ответ объявлен частичным.** REV-001: студент передал суть с использованием `RAM`, но baseline не восстановил всю семантическую связь. Боль высокая: студент получает заниженную оценку.
2. **Спорная эталонная разметка.** REV-021, REV-024 и REV-039 содержат почти дословный ожидаемый ответ, но размечены как `partially_correct`; модель ставит `correct`. Автоматически эталон не подгоняем — нужно ручное решение Quality/Product.
3. **Повторы карточек на коротком тексте (закрыто в cards-v2.0).** GEN-LIVE-001: схема и grounding были зелёными при однообразной тренировке. Теперь генератор возвращает только независимые карточки и допускает набор меньше пяти.
4. **Технические разрывы UC-03/04 (закрыты).** Первый прогон не имел рейтинга и resume. После исправления оценка и позиция сессии сохраняются; проверяет E2E smoke и ручной проход Дениса.
5. **Обрывы формулировок и feedback (AI-MANUAL-01/02, открыто).** На живом Telegram вопросы и пояснения режут слова. Schema/grounding это не ловят — боль пользователя высокая, приоритет P0 спринта 4.

## Что бьёт по пользователю / что терпимо

| Класс | Решение Product |
|---|---|
| Заниженный review короткого верного ответа | нетерпимо в спринте 4 |
| Спорные эталоны без ручного ревью | нетерпимо оставлять без решения |
| Шаблонный тон deterministic fallback | терпимо для демо Lab 3 |
| Обрывы вопросов и feedback на живом боте | нетерпимо; P0 |
| Review agreement deterministic &lt; 85% | нетерпимо |

## Приоритет AI Engineer по боли (не по частоте)

1. Исправить AI-MANUAL-01/02: целостный тезис в вопросе и понятный feedback.
2. Вручную пересмотреть четыре оставшихся расхождения эталонов, не меняя expected автоматически.
3. Сохранить проверку независимых тезисов и отдельную метрику дублей в будущем Gemini-прогоне.
4. Сравнить Gemini с тем же dataset; средняя цифра без разреза по verdict не принимается.
