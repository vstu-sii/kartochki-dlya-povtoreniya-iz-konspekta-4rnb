# Ручное подтверждение дополнений golden dataset v2

Автоматический прогон не может подтвердить правильность эталона. Для каждой новой строки нужны два реальных проверяющих. Проверяющий сверяет вход, ожидаемый результат, связь с UC и отсутствие подгонки под ответ модели.

| GEN-LIVE-001 |  |  |  | ожидает проверки |
| GEN-LIVE-002 |  |  |  | ожидает проверки |
| REV-LIVE-001 |  |  |  | ожидает проверки |
| REV-LIVE-002 |  |  |  | ожидает проверки |
| SAFE-LIVE-001 |  |  |  | ожидает проверки |
| SAFE-LIVE-002 |  |  |  | ожидает проверки |
| STATE-LIVE-001 |  |  |  | ожидает проверки |
| UX-LIVE-001 |  |  |  | ожидает проверки |

После реальной проверки участники заменяют статус на `approved` и в соответствующей JSONL-строке меняют `human_review` с `pending` на объект с именами и датой. Пустая таблица не считается подтверждением.
