# Golden dataset v1

**Файл:** `dataset.jsonl`  
**Версия:** `lab2-v1` · 2026-09-28  
**Объём:** 36 пар «вход → эталон».  
**Владелец:** Quality & Safety; изменения — только через PR с человеческим ревью.

## Состав

- `GEN-001…GEN-016` — генерация grounded-карточек по синтетическим учебным фрагментам (UC-01);
- `REV-001…REV-010` — оценка верных, частичных и неверных ответов (UC-02);
- `UX-001…UX-002` — оценка полезности карточки (UC-03);
- `STATE-001…STATE-002` — завершение и возобновление сессии (UC-04);
- `SAFE-001…SAFE-006` — лимиты ввода, prompt injection, недостаточный контекст и неподтверждённая цитата (UC-05).

**Объём:** 36 пар. Большая часть покрывает AI-операции; UX/STATE задают эталоны прикладного API Delivery для лабы 3. Каждая запись содержит `use_case`, `context`, вход, ожидаемый результат и теги.

## Происхождение

Фрагменты написаны командой как короткие демонстрационные формулировки по типовым темам; это не копии закрытых методичек и не ответы модели. Перед production их дополняют обезличенными фрагментами реальных материалов, на использование которых у команды есть право. Эталон проверяет человек, знакомый с темой.

## Формат

JSON Lines: одна независимая JSON-запись в строке. Минимальные поля: `id`, `dataset_version`, `use_case`, `operation`, `input`, `context`, `expected_output`, `tags`, `source`.

**Выбранный инструмент MVP:** `pytest` с небольшим типизированным adapter/runner в лабораторной 3. Формат уже читается построчно стандартным `json.loads`; это проверяет `tests/test_lab2_all_artifacts.py`. При необходимости те же записи преобразуются в объекты pydantic-evals без изменения canonical dataset.

`generate_card` оценивается по ожидаемому вопросу/ответу, обязательной цитате и отсутствию запрещённых фактов. `review_answer` ожидает verdict и ключевые пункты. `reject_input` ожидает стабильный код ошибки. Формат читается Python, pytest, pydantic-evals и конвертируется в promptfoo/DeepEval.

## Процесс изменения

1. Привязать кейс к UC и реальному дефекту/риску.
2. Указать происхождение и право использования.
3. Два человека проверяют эталон; автор prompt/model change не подтверждает его один.
4. Не менять старый expected только ради зелёного прогона — сначала решить, изменилось ли требование.
5. Повысить `dataset_version`, сохранить baseline по model/prompt/schema version.

## Будущие пороги

Порог назначается после baseline. Начальные критерии из test plan: schema 100% после ≤1 repair, grounded cards ≥95%, полезность ≥80%, противоречия review ≤5%. Спорные LLM-judge результаты проверяет человек.
