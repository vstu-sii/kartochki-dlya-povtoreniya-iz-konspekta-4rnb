# Критерии успеха

Согласовано с Product по болям из `docs/prd.md`. Каждый критерий измерим: число плюс способ подсчёта.

## Качество ответов бота

- **Полезность карточек:** не менее 80% сгенерированных вопросов пользователь помечает как полезные/по теме. Считаем: кнопка оценки после каждого вопроса, доля положительных оценок от общего числа.
- **Точность выделения тезисов:** не менее 75% тезисов признаны верными при ручной проверке на тестовой выборке PDF. Считаем: ревьюер сверяет тезисы с оригиналом методички, доля совпадений.
- **Качество разбора устного ответа:** отклик бота на ответ пользователя не должен противоречить эталону из golden dataset. Считаем: ручная сверка на выборке из 20 разборов, доля без противоречий.

## Инженерные метрики

- **Время генерации набора вопросов из PDF:** менее 1 минуты от загрузки до готового набора. Считаем: логируем таймстемпы старт/финиш на бэкенде.
- **Задержка разбора одного устного ответа:** не более 5-7 секунд. Считаем: логируем время от получения сообщения до ответа бота.
- **Стоимость запроса:** укладываемся в бюджет из `docs/model-candidates.md`. Считаем: сумма токенов на сессию умножить на цену провайдера.

## Что меряем автоматически с лабы 3

Автоматический прогон golden dataset через пайплайн бота с подсчётом метрик выше на каждый PR, без ручной проверки каждый раз.

## Соответствие болям из PRD

| Боль | Что значит что продукт её решает |
|---|---|
| Мало времени | Набор вопросов готов меньше чем за минуту после загрузки PDF |
| Не понятно что спросят | Минимум 80% вопросов оценены пользователем как релевантные |
| Разное качество конспектов | Точность извлечения тезисов не ниже 75% на разных по структуре PDF |
| Нет обратной связи | Пользователь получает разбор каждого устного ответа за 5-7 секунд |
| Формулы теряются | Отдельно считаем долю пропущенных формул в извлечённых тезисах, цель меньше 10% |
