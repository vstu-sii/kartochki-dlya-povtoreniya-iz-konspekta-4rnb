# Скриншоты Lab5 — инструкция сбора

Статус на 22.10.2026: [скриншот CI v0.5.1 уже есть у Delivery](https://github.com/vstu-sii/kartochki-dlya-povtoreniya-iz-konspekta-4rnb/blob/9f5e81504f33a18838a062af4a0e5623e63764b7/docs/evidence/lab5/v0.5.1-quality-gate.png); скриншот Grafana с данными ещё ожидается. Изображение CI не копируется в Quality. Ниже инструкция для дополнительных кадров и нового релиза; наличие инструкции не закрывает требование.

## 1. Успешный релизный прогон

1. Открой https://github.com/vstu-sii/kartochki-dlya-povtoreniya-iz-konspekta-4rnb/actions/runs/39221429651 .
2. Проверь имя `Lab5 release quality gates`, тег `v0.5.1`, коммит `e0ca9b9` и зелёный итог.
3. Сними экран с этими сведениями: Win+Shift+S; сохрани PNG как `release-gate-v0.5.1.png` рядом с этой инструкцией.
4. Открой job `release-quality`, раскрой шаг запуска `run_release_evals.py`. Сними строки результатов и покрытие 132/132 как `release-results-v0.5.1.png`.
5. Внизу страницы запуска скачай артефакт `lab5-quality-v0.5.1`. Проверь внутри JSON: release_ref=v0.5.1, commit=e0ca9b9..., passed=true. При истечении срока хранения нужен новый запуск на теге; старый закоммиченный RC JSON не заменяет артефакт.

## 2. Дашборд с данными

1. Попроси Delivery открыть Grafana работающего контура и назвать версию и окружение. Для локального staging на выделенной копии проекта используется `docker compose -f compose.yml -f compose.staging.yml up --build -d`; нужен Docker Desktop и заполненные переменные окружения. Не запускай второй контур поверх занятого без проверки портов.
2. Для этого staging открой http://localhost:3002 . Войди с учётными данными Delivery. При отсутствии переопределений в Compose: пользователь admin, пароль staging-change-me; уже созданный volume может хранить другие данные.
3. Открой Dashboards и дашборд проекта. Выполни несколько обычных действий в приложении: создание карточек и проверку ответа. Дождись появления метрик.
4. Выбери диапазон Last 15 minutes или Last 1 hour и нажми Refresh. Если панели показывают No data, сначала проверь сбор метрик с Delivery — такой снимок не подтверждает работу мониторинга.
5. Сними заголовок, диапазон времени и панели request rate, latency, errors. Сохрани как `dashboard.png`. При необходимости сделай отдельный снимок состояния alerts. Не включай пароли, токены и личные тексты пользователей.
6. Подпиши ниже фактические дату, окружение, тег/SHA, что проверяли. Локальный staging не подписывай как production; время на скриншоте должно относиться к фактическому запуску.
