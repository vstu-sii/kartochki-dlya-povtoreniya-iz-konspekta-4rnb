# Глоссарий команды

Единый словарь предметной области, архитектуры и AI-пайплайна. Новые термины добавляются в том же спринте, в котором появились в ADR, OpenAPI или схеме данных.

| Термин | Определение |
|---|---|
| Конспект | Исходный документ пользователя: методичка или запись лекции в PDF, из которого система извлекает материал |
| Тезис | Один ключевой пункт из конспекта, вокруг которого строится вопрос для повторения |
| Карточка | Пара «вопрос — эталонный ответ» с привязкой к странице и цитате; базовая единица повторения |
| Раунд вопрос–ответ | Один цикл: бот показывает вопрос, студент отвечает текстом, система возвращает вердикт и обратную связь |
| Разбор ответа | Сверка ответа студента с эталоном и перечисление пропущенных пунктов |
| Сессия | Один заход пользователя от загрузки PDF до завершения или сохранения прогресса набора карточек |
| Защита лабы | Устный опрос преподавателем по теории лабораторной работы; целевое событие, к которому готовится пользователь |
| Эталонный ответ | Краткая формулировка правильного ответа, с которой сравнивается ответ студента |
| Golden dataset | Версионируемый набор пар «вход — эталон» для воспроизводимых evals |
| North Star | Главная продуктовая метрика: доля карточек, отмеченных пользователем как полезные |
| Prompt injection | Попытка через содержимое PDF или ответа заставить модель нарушить системные инструкции |
| Токен-бюджет | Ограничение числа токенов LLM на операцию или сессию для контроля стоимости и задержки |
| DoD | Definition of Done — проверяемые критерии готовности артефакта |
| ADR | Architecture Decision Record, запись про выбор технического подхода с указанием цены решения |
| AI gateway | Единственная внутренняя точка обращения к LLM-провайдеру; выбирает primary/fallback и нормализует ошибки |
| Primary model | Основная модель, на качестве и цене которой рассчитан штатный сценарий |
| Fallback model | Более дешёвая резервная модель для одного повторного вызова при timeout, 429 или 5xx primary |
| Structured output | JSON-ответ модели, проверяемый по заранее заданной схеме, а не разбираемый из свободного текста |
| Grounding | Проверяемая опора карточки на переданный источник; в MVP подтверждается страницей и дословной цитатой |
| Source quote | Короткая дословная цитата из страницы PDF, подтверждающая вопрос и эталонный ответ |
| Контекст модели | Данные, реально переданные модели в одном вызове; не равен всей информации, доступной приложению |
| Контекстный guard | Проверка объёма, языка и пригодности текста до вызова модели |
| Prompt version | Версия системных инструкций, записываемая с результатом для воспроизводимости evals |
| Schema version | Версия формата `CardSet` или `AnswerReview`, согласованная между AI и Delivery |
| Repair-вызов | Единственная повторная генерация для исправления машинно обнаруженной ошибки структуры или grounding |
| Idempotency key | Ключ, не позволяющий повторному запросу создать второй набор или вторую проверку ответа |
| Trace ID | Сквозной технический идентификатор запроса в логах без содержимого PDF и ответа студента |
| Card set | Набор из 5–10 карточек, созданный из одного документа и одной версии промпта |
| Answer review | Структурированный вердикт по ответу: оценка, обратная связь и пропущенные пункты |
| Text layer | Машиночитаемый текст внутри PDF; скан без него не поддерживается в MVP |
| C4 Context | Диаграмма границы системы, людей и внешних систем без внутренних контейнеров |
| C4 Container | Диаграмма отдельно запускаемых приложений и хранилищ внутри системы |
| ACL | Anti-corruption layer — адаптер, изолирующий доменную систему от API внешнего провайдера |
| Repo/relay | Контейнер-владелец БД, через который остальные контейнеры читают и меняют мастер-данные |
| Evals | Воспроизводимые проверки поведения AI на версионируемом наборе примеров |
