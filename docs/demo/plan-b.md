# План Б Demo Day

## AI: отказ или задержка модели

### Когда переключаемся

- Gemini не отвечает 30 секунд;
- API возвращает 429/5xx;
- ответ содержит `fallback_used=true`;
- контракт/grounding отклоняет ответ;
- Wi‑Fi не позволяет продолжить публичный сценарий.

### Что происходит в продукте

Приложение перехватывает ошибку провайдера и возвращает карточки локального `deterministic-grounded-v2`. В ответе сохраняются `model`, `fallback_used`, `fallback_reason` и `trace_id`; деградация не маскируется под Gemini. Fallback-ответ после временной ошибки не кладётся в долгий кэш, поэтому восстановившийся провайдер можно использовать следующим запросом.

В пользовательском Telegram-интерфейсе после успешного fallback показывается сообщение: «Готово: создано 5 карточек резервным алгоритмом. Начинаем повторение». Пользователь получает карточки и может продолжить сценарий, но явно видит, что их создала не языковая модель. Если backend не смог вернуть даже резервный результат, пользователь видит сообщение о временной ошибке и просьбу повторить попытку через минуту.

### Что делает выступающая

1. Называет факт: «Внешняя модель сейчас медленная/недоступна; показываю предусмотренную деградацию».
2. Если API уже вернул fallback — показывает карточки и поля `model`/`fallback_used`.
3. Если сеть недоступна — открывает `docs/demo/cache/ai-demo-backup-v0.5.10.json` через ноутбук `notebooks/lab6_demo_cases.ipynb`.
4. Явно говорит, что это сохранённый ответ репетиции, а не live-вызов.
5. Возвращается к сценарию с разбором цитаты и ограничений.

### Как проверено

В `tests/evals/run_lab6_demo.py` провайдерный timeout инъецируется через mock без настоящего ключа и без отключения production. Проверка 30.10.2026 на коде AI и проверка пользовательского сообщения в Delivery-коде тега `v0.5.10-demo-candidate` подтвердили:

- `fallback_used=true`;
- `fallback_reason=gemini_timeout`;
- `model=deterministic-grounded-v2`;
- получено 5 карточек;
- `trace_id` присутствует.
- Telegram на `fallback_used=true` пишет «резервным алгоритмом», а не «языковой моделью».

Сырой результат находится в `artifacts/demo/lab6-ai-demo-v0.5.10.json`, раздел `fallback_probe`. Пользовательская ветка находится в `telegram_bot/app.py`: выбор текста выполняется по `result.get("fallback_used")`. Отдельные unit-тесты проверяют, что fallback не кэшируется после восстановления провайдера.

### Кэш ключевых кейсов

`docs/demo/cache/ai-demo-backup-v0.5.10.json` содержит первый успешный ответ каждого из пяти кейсов и результат проверки деградации. Файл не содержит API-ключей, промптов и пользовательских PDF. Перед выступлением его нужно открыть заранее; использовать только как явно обозначенный статический бэкап.

## Ответственность на сцене

- AI Engineer следит за `model`, `fallback_used`, цитатами и временем.
- Delivery заранее открывает public URL, `/health` и видео-бэкап.
- Product продолжает рассказ, если переключение занимает больше 30 секунд.
- Quality не позволяет выдавать кэшированный ответ за live и фиксирует показанное ограничение.
