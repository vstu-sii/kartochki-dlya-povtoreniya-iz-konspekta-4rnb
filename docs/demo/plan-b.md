# План Б для Demo Day

## Основной сценарий

1. Открыть публичный URL и показать `/health`.
2. В Telegram открыть бота, выполнить `/start`, отправить подготовленный PDF.
3. Показать карточку с вопросом. В текущей версии Telegram источник и цитата пользователю не отображаются.
4. Ответить своими словами, показать смысловую проверку и перейти к следующей карточке.

## Если недоступен Gemini

Приложение не отдаёт пользователю ошибку провайдера: после ограниченных повторов
включается локальный grounded baseline, карточки остаются привязаны к страницам и
цитатам. Проверка выполняется командой:

```bash
python scripts/demo-rehearsal.py
```

Фактический результат хранится в `artifacts/demo/plan-b-rehearsal.json`.

## Если недоступен Wi-Fi или Render

1. Переключить ноутбук на заранее проверенный мобильный интернет.
2. Если публичный сервис не восстановился за 30 секунд, открыть локальный файл
   `docs/demo/demo-backup.mp4` — он лежит рядом с презентацией и не требует сети.
3. После видео открыть сохранённый `artifacts/demo/plan-b-rehearsal.json` и
   объяснить, что отказ модели обработан кодом, а не скрыт монтажом.

Видео проверяется скриптом на наличие и читаемость. Перед выходом оно открывается
локальным проигрывателем; копия также хранится на флешке команды. Мобильный канал
проверяется ответственным Delivery в день репетиции и ещё раз перед выступлением.

## Быстрая команда полной репетиции

```bash
python scripts/demo-seed/reset_demo.py
python scripts/demo-rehearsal.py --public-url https://kartochki-dlya-povtoreniya-iz-konspekta.onrender.com
```

Скрипт проверяет, что возвращена хотя бы одна карточка с `fallback_used=true`, файл видео существует и больше 10 КБ, а публичный `/health` отвечает HTTP 200. Размер файла не доказывает воспроизведение видео; его нужно отдельно открыть и проверить. Это локальная симуляция отказа провайдера, а не проверка отказа через Telegram на проде.
