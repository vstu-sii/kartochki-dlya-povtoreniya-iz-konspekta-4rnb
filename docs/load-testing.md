# Нагрузочное тестирование Lab 5

```powershell
python tests/load/run_uc_load_test.py --base-url http://127.0.0.1:8095 --levels 1,5,10,20,40,80,120 --requests-per-level 40 --p95-limit-ms 500
```

Основной замер идёт по UC-01: HTTP API вызывает модель и сохраняет пять карточек в БД. SLO локального контура: error rate ≤1%, p95 ≤500 мс. Полный результат лежит в `artifacts/load/lab5-uc-load-results.json`.

После поиска предела отдельный профиль фиксирует разные типы пользовательской нагрузки при подтверждённой concurrency 5:

```powershell
python tests/load/profile_uc_paths.py --base-url http://127.0.0.1:8095 --concurrency 5 --requests 40
```

Он измеряет UC-01 (генерация + модель + запись), UC-02 (проверка ответа + модель + запись) и UC-04 (возобновление + чтение БД) и сохраняет их раздельно в `artifacts/load/lab5-uc-profile.json`. UC-03 не выделяется в нагрузочный профиль, потому что это короткая запись rating; UC-05/06/07 являются ветвями отказа и покрываются integration/security tests, а не массовым прогоном против production.

Фактический профиль 19.10.2026 при concurrency 5 и 40 запросах на путь: UC-01 — p50 120,34 мс / p95 283,33 мс; UC-02 — 71,73 / 96,33 мс; UC-04 — 37,48 / 61,93 мс. Ошибок во всех трёх профилях 0%. Это локальный deterministic + SQLite контур; цифры не подменяют Gemini/production latency.

Фактический прогон 19.10.2026: уровни 1 и 5 прошли с 0% ошибок, p95 56,51 и 146,83 мс. Уровень 10 дал 0% ошибок, но p95 **1016,92 мс**, поэтому первый предел по SLO — **10 одновременных генераций**, подтверждённая устойчивая нагрузка — **5**. Узкое место — синхронная запись SQLite и последовательные участки in-process deterministic-модели; это локальный измерительный контур, а не обещание пропускной способности Gemini/Render.

Отдельный безопасный smoke публичного `/health` сохранён в `artifacts/load/lab5-load-results.json`: он проверяет доступность, но не используется как предел бизнес-сценария.
