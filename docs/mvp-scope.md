# Зафиксированный MVP к Demo Day

## Входит

- Telegram-бот и web-интерфейс принимают PDF до 10 МБ и 40 страниц.
- Система создаёт 5–10 карточек только по извлечённому материалу.
- Ответ своими словами получает verdict, объяснение и недостающие пункты.
- Прогресс, оценки карточек и результаты модели сохраняются в БД.
- Повторный вход восстанавливает незавершённую сессию.
- На пользователя действуют суточные лимиты запросов и токенов; после 80% бюджета используется дешёвая модель.
- CI запускает тесты и полный eval-набор, merge в `main` запускает деплой.
- Staging собирается из того же Compose-контура, что production.
- Grafana показывает HTTP-метрики, логи, LLM-трейсы и срабатывания бюджета.
- Prompt injection из известного набора блокируется кодом.

## Явный не-скоуп

- Подготовка сразу по нескольким PDF — исключена, чтобы не смешивать источники и сохранить проверяемый grounding.
- Редактор карточек преподавателем — исключён: для Demo Day проверяется автоматический путь, а не CMS.
- Платежи и подписки — исключены до подтверждения удержания пользователей; иначе платёжный контур создаст непропорциональный риск.
- Голосовые ответы — исключены из-за отдельной стоимости и ошибок распознавания речи.
- Полнотекстовый RAG по библиотеке — исключён: один PDF помещается в ограниченный контекст, а выгода поиска ещё не доказана.
- Горизонтальное масштабирование limiter через Redis — исключено для одного production-инстанса; интерфейс limiter отделён для замены в следующем спринте.
- Автоматическое исправление спорных эталонов — исключено: golden dataset меняется только после ручного ревью.

Скоуп заморожен 19.09.2026. Изменение допускается только обменом: новый пункт добавляется после удаления равного или большего объёма.
