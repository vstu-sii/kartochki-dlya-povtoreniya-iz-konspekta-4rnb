# ADR-003: Синхронный пайплайн без очереди в MVP

## Контекст

Генерация карточек — одна модельная операция на документ. Очередь и worker повышают устойчивость, но требуют брокер, отдельную модель состояний и доставку уведомлений. В MVP ожидается низкая учебная нагрузка.

## Решение

Application API синхронно вызывает AI Service. Общий timeout генерации — 60 секунд, проверки ответа — 10 секунд с fallback. `Idempotency-Key` предотвращает дубли при повторе клиента. Очередь не используется.

## Обоснование

Синхронная схема проще для прототипа и сохраняет линейную трассу запроса. В интерфейсе Telegram показывается состояние «Готовлю вопросы», а timeout превращается в управляемую ошибку с повтором.

## Цена решения

Длинный HTTP-запрос занимает соединение и хуже переживает перезапуски. Нет гарантированной фоновой доставки результата. Если генерация стабильно выходит за 60 секунд или появляется параллельная нагрузка, потребуется очередь, worker и endpoint статуса — это осознанный архитектурный долг.

## Как покрыть тестами

- повтор с тем же `Idempotency-Key` создаёт один card set;
- timeout primary приводит максимум к одному fallback-вызову;
- превышение общего бюджета времени возвращает стабильный 503;
- нагрузочный тест фиксирует p95 и число одновременных запросов.
