# ADR-002: Единый владелец данных и ограниченное хранение

**Статус:** принято 2026-09-28.

## Контекст

Сессии, карточки, ответы и оценки должны быть согласованы. Полный текст учебного PDF может содержать персональные или закрытые сведения и не нужен после подготовки. Прямой доступ нескольких сервисов к одной БД создаст неявные контракты.

## Решение

Data Service — единственный контейнер с CRUD-доступом к PostgreSQL. Остальные используют его внутренний HTTP API. Бинарный PDF не сохраняется после извлечения; нормализованный текст и page map хранятся не более 24 часов, затем удаляются. Карточки и обезличенный прогресс хранятся 30 дней. API-ключи и полные промпты в БД не попадают.

Схема: `database/schema.sql` и `docs/architecture/erd.puml`.

## Обоснование

Отдельное объектное хранилище и event sourcing отклонены как избыточные для MVP. PostgreSQL достаточно для ожидаемого объёма и транзакционной целостности.

## Цена решения

Data Service добавляет сетевой hop и становится критической зависимостью. Очистка по TTL требует фоновой задачи и теста. Без долговременного исходного PDF некоторые ошибки нельзя будет воспроизвести; для воспроизводимости сохраняются хеш, версия парсера, prompt/schema version и разрешённые короткие цитаты.

## Как покрыть тестами

- миграции поднимаются на пустой БД и повторно не применяются;
- только Data Service имеет `DATABASE_URL`;
- интеграционный тест TTL удаляет исходный текст, но оставляет агрегированные метрики;
- тест разграничения не выдаёт сессии другого Telegram user id.
