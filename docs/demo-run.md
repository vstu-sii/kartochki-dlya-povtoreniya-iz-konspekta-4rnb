## Команды воспроизведения

Из корня репозитория:

```powershell
py -3 -m tests.evals.run_lab6_demo --repeats 3 --pause-seconds 1
```

Если ответы уже записаны и изменился только код проверки результата:

```powershell
py -3 -m tests.evals.run_lab6_demo `
  --revalidate-existing artifacts/demo/lab6-ai-demo-run.json `
  --output artifacts/demo/lab6-ai-demo-run.json
```

Вторая команда не вызывает Gemini: она повторно проверяет сохранённые raw HTTP responses. Этот режим использован после исправления валидатора, который первоначально искал правильное исправление только в `feedback`, хотя контракт также разрешает `missing_points`.

Ноутбук `notebooks/lab6_demo_cases.ipynb` показывает сводку, таблицу пяти кейсов и сохранённый бэкап; сам источник логики — versioned runner `tests/evals/run_lab6_demo.py`.

## Интерпретация

Функциональная часть выбранных демо-кейсов стабильна: карточки имеют ровно пять элементов и grounded-цитаты; три типа review стабильно различаются; ошибочная ссылка на жёсткий диск исправляется. Однако цель review ≤7 с не гарантируется: два review-кейса и генерации превышали её, общий p95 равен 20,393 с. Для выступления обязателен Plan B с порогом переключения 12 секунд.

## Граница доказательства

Это реальный публичный прогон на задеплоенном интеграционном candidate-теге, но не подтверждение окончательного командного demo freeze: тег называется `candidate`, а не финальным Demo Day release. После назначения командой окончательного неизменяемого тега нужно один раз повторить ту же команду, проверить SHA из `/health` и заменить этот раздел новым артефактом. Нельзя переписывать поле SHA вручную без прогона.
