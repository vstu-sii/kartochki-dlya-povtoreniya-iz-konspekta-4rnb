# PRD v3 — карточки для повторения из конспекта

## Проблема

Студенту трудно превратить длинный PDF-конспект в короткий набор вопросов для устной защиты и объективно проверить ответ, сформулированный своими словами.

## Пользователь и основной сценарий

Студент загружает один PDF, получает 5–10 grounded-карточек, отвечает на них в Telegram или web-интерфейсе, видит объяснимую оценку и продолжает с сохранённого места.

## Требования v3

1. Карточка обязана содержать страницу и дословную цитату из загруженного PDF.
2. Проверка принимает синонимы и смысловой эквивалент, но не принимает противоречие источнику.
3. Ошибка модели, лимит или таймаут отображаются понятным сообщением и не повреждают сессию.
4. Необратимые операции и доступ к данным разрешает приложение, а не LLM.
5. Не более 50 модельных запросов и 120 000 оценочных токенов на пользователя в сутки; после 80% применяется дешёвая модель.
6. Повторный запрос с тем же idempotency key не списывает бюджет и не создаёт дубликат.
7. Каждый релиз проходит unit/integration/security tests и полный golden eval.

## North Star и защитные метрики

- **North Star:** не менее 70% начатых учебных сессий завершаются минимум по пяти карточкам.
- Не менее 85% внешних пользователей завершают UC-01…UC-05 без подсказки команды.
- Schema validity и grounding — 100% на golden dataset.
- Review agreement — не ниже 85%; текущая точка отсчёта 90,48% deterministic fallback.
- p95 ответа API без провайдера — до 500 мс; p95 модельного вызова отслеживается отдельно.
- Доля запросов, завершившихся непонятной ошибкой, — менее 2%.
- Бюджетная аномалия создаёт алерт до превышения суточного лимита.

## Ограничения и риски

Цифры fallback нельзя выдавать за качество или latency Gemini. Для публичной продажи нужны управляемая production-БД, резервное копирование, Redis limiter при масштабировании и отдельная юридическая проверка пользовательских документов.

Полный scope и причины исключений: `docs/mvp-scope.md`.
