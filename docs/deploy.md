# Деплой

## Прод URL

`ВСТАВИТЬ_ССЫЛКУ_ПОСЛЕ_ДЕПЛОЯ`

Это единственное поле в документах лабы 1, которое нельзя заполнить заранее, ссылка появляется только после реального деплоя. Delivery выполняет шаги ниже и вписывает готовую ссылку сюда и в README.

## Куда деплоим

Render.com, бесплатный тариф. Причины: не нужна карта для бесплатного тарифа, поддерживает деплой из Dockerfile напрямую, даёт публичный HTTPS URL из коробки.

## Как задеплоить

1. Зарегистрироваться на render.com через GitHub аккаунт
2. Создать новый Web Service, выбрать этот репозиторий
3. В настройках указать Environment: Docker, путь к Dockerfile: корень репозитория (`Dockerfile`)
4. Порт указать 8080 (совпадает с портом в Dockerfile и compose.dev.yml)
5. Нажать Deploy, дождаться сборки образа
6. Скопировать выданный публичный URL вида `https://имя-сервиса.onrender.com`
7. Вписать ссылку в это поле выше и в README.md в раздел "Прод"
8. Проверить что страница открывается у другого члена команды с другого устройства, не только у того кто деплоил

## Кто может передеплоить

Пока только Delivery, доступ к Render у него один. Если бесплатный тариф Render не подойдёт по лимитам (например сервис засыпает при простое), запасной вариант Railway.app с похожим бесплатным тарифом.

## Что дальше

В лабе 2-3, когда появится реальный backend с ботом, этот же процесс деплоя переиспользуем, просто Dockerfile соберёт уже настоящее приложение, а не hello-world заглушку.
