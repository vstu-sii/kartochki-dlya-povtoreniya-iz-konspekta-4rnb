# Нарратив Demo Day

## Каркас истории (боль → решение → цифры)

1. **Боль.** Из длинного PDF трудно быстро сделать вопросы и понять, верен ли свободный ответ (боли PRD, приёмка — `docs/acceptance.md`).
2. **Сценарий.** Загружаем PDF в Telegram, получаем пять grounded-карточек, отвечаем своими словами, видим вердикт и цитату, продолжаем с сохранённого места.
3. **Доказательство системы.** UI → API → модель → БД проходит E2E; grounding и schema — 100% на frozen dataset; полный Quality-набор покрывает 132/132 кейса. Публичный smoke 19.10: `artifacts/product/lab5-prod-uc.json`.
4. **Почему эта AI-версия.** Реальный Gemini A/B: prompt B — 100% против 95% у A на 20 кейсах, цена 6380 против 3843 токенов. После точечной Lab5-правки deterministic review — 92,86% против 90,48% ранее и выше порога 85%; fallback сохранён.
5. **Надёжность и безопасность.** Отказ модели и БД → штатный 503; атаки повторно прогоняются; необратимые действия остаются у приложения.
6. **Пользовательский результат (North Star).** Цель ≥70% сессий с пятью карточками. Замер способом из PRD по `study_sessions`: внешний студент **Постернак Денис** — **1/1 = 100% (+30 п.п.)** (`docs/north-star.md`). Честная оговорка: n=1, для подтверждения нужно ≥10 внешних сессий — это P0 до демо.
7. **Ограничения (называем сами).** Один PDF; OCR зависит от скана; Gemini A/B на малой выборке; `X-User-ID` — не полноценная auth; Redis нужен перед продажей.

Финал: концепция технически доказана и измерена; следующий риск — повторяется ли пользовательская ценность на достаточной выборке.

| Слайд | Заголовок | Что показать | Цифра / источник |
