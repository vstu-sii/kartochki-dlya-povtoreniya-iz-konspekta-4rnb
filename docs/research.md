# Ресёрч

## Узкий ресёрч: жива ли проблема

Готовые сервисы для карточек (Anki, Quizlet) уже давно умеют превращать конспект в набор карточек, но делают это либо вручную, либо через сторонние плагины и промпты, которые пользователь пишет сам. Это подтверждает что боль реальная, люди сами придумывают обходные пути, но готового узкого решения именно под устную защиту лабы нет.

- В Quizlet есть встроенная функция генерации карточек из вставленного текста конспекта или PDF, а также функция Magic Notes, которая структурирует хаотичные заметки в карточки с определениями. Источник: [обзор Quizlet, sborka.ai](https://sborka.ai/products/quizlet)
- При этом другой источник уточняет что генерация карточек это платная функция (нужна подписка Quizlet Plus) и что прямой загрузки PDF или ссылки на видео в базовом сценарии нет, текст сначала нужно извлечь самому. Источник: [Lynote Blog о Quizlet AI](https://lynote.ai/ru/blog/create-flashcards-with-quizlet-ai)
- В Anki нет встроенной генерации карточек из текста, пользователи вручную копируют конспект в ChatGPT, просят сделать карточки и импортируют результат через плагины. Источник: [опыт использования ChatGPT с Quizlet, t-j.ru](https://t-j.ru/chatgpt-for-kartochki-quizlet/)

Вывод: рынок явно видит боль "автоматически сделать карточки из конспекта", но у всех решений это отдельная фича внутри большого приложения, заточенная под карточки для чтения глазами, а не под устный прогон перед конкретной защитой лабы.

## Широкий ресёрч: аналоги и подходы

Сравнили три направления подходов:

1. **Готовые сервисы карточек с AI-генерацией (Quizlet AI, плагины Anki).** Quizlet генерирует карточки из текста и заметок, а распространённый сценарий с Anki требует сначала получить карточки от LLM, затем импортировать их. Основание: [обзор функций Quizlet](https://sborka.ai/products/quizlet), [описание ограничений Quizlet AI](https://lynote.ai/ru/blog/create-flashcards-with-quizlet-ai), [пользовательский сценарий генерации и импорта карточек](https://t-j.ru/chatgpt-for-kartochki-quizlet/). Вывод о том, что эти решения не ориентированы на устную защиту конкретной лабораторной, — результат сравнения их описанных сценариев с нашим PRD.
2. **RAG-чат с PDF-документом.** RAG добавляет к генератору отдельный поиск по внешнему индексу; исходная статья описывает связку генеративной модели, dense vector index и retriever: [Lewis et al., 2020](https://arxiv.org/abs/2005.11401). Сервисы класса [ChatPDF](https://www.chatpdf.com/) дают диалог с документом, но пользователь сам формулирует вопросы. Для нашей боли «не знаю, что спросят» этого недостаточно без отдельного шага автоматической генерации вопросов — это продуктовый вывод команды из сравнения сценария сервиса с PRD.
3. **Прямая генерация вопросов и ответов промптом к LLM без RAG.** Этот вариант технически возможен, когда текст целиком помещается в контекст модели. У рассмотренных кандидатов контекст существенно больше принятого командой лимита методички в 25 000 токенов: [Gemini 3.8 Flash — 1 048 576 входных токенов](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash), [Qwen3.5-27B — 262 144 токена](https://huggingface.co/Qwen/Qwen3.5-27B), [GigaChat 3 Ultra — 128 000 токенов](https://developers.sber.ru/docs/ru/gigachat/models/updates).

Для нашего узкого случая (одна методичка, PDF, 10–20 страниц) вариант 3 выглядит достаточным на старте. Это проверяемое архитектурное предположение команды: если качество прямого промпта на golden dataset не достигнет согласованных командой критериев качества, решение пересматривается в пользу RAG.

## Узкий ресёрч: детали для выбора подхода

Проверили ограничение по объёму контекста у кандидатов моделей, разбор приведён в `docs/model-candidates.md`. Для проектирования команда приняла консервативный внутренний лимит одной методички **25 000 токенов**; это не внешняя статистика, а ограничение MVP, которое будет проверяться токенизатором перед запросом. Официальные окна контекста кандидатов — [1 048 576 у Gemini 3.8 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash), [262 144 у Qwen3.5-27B](https://huggingface.co/Qwen/Qwen3.5-27B) и [128 000 у GigaChat 3 Ultra](https://developers.sber.ru/docs/ru/gigachat/models/updates) — превышают этот лимит. Поэтому RAG не требуется именно для соблюдения ограничения контекста в MVP; его возможное влияние на качество проверим отдельно.

## Решение (ADR-001: выбор подхода)

**Статус:** решение принято для лабы 1, пересмотрим в лабе 2 если объём конспектов вырастет.

**Контекст:** нужно выбрать как система вытаскивает тезисы и генерирует вопросы из PDF методички: прямые промпты к LLM, RAG над содержимым PDF, или агент с несколькими шагами (поиск, уточнение, генерация).

**Решение:** берём прямые промпты к LLM. Текст PDF извлекаем целиком (библиотекой для парсинга PDF) и одним промптом просим модель выделить 5–10 ключевых тезисов и сформулировать по ним вопросы. Решение опирается на подтверждённые окна контекста кандидатов: [Gemini](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash), [Qwen](https://huggingface.co/Qwen/Qwen3.5-27B), [GigaChat](https://developers.sber.ru/docs/ru/gigachat/models/updates). Без RAG и без многошагового агента.

**Альтернативы и почему отказались:**

- **RAG над PDF:** отложили, потому что документы MVP помещаются в контекст целиком. RAG требует отдельного непараметрического индекса и retriever — эти компоненты описаны в [исходной статье RAG](https://arxiv.org/abs/2005.11401). Для нашего объёма выигрыш в качестве ещё не подтверждён экспериментом, поэтому добавление этих компонентов преждевременно.
- **Многошаговый агент (сначала план, потом обработка по частям):** отложили на первой итерации. Это решение команды, основанное на простой проверяемой зависимости: несколько последовательных вызовов требуют больше API-запросов, чем один прямой вызов, а тарификация облачных моделей зависит от обработанных входных и выходных токенов ([тарифы Gemini API](https://ai.google.dev/gemini-api/docs/pricing)). Выигрыш для методичек 10–20 страниц пока не подтверждён.

**Цена решения:** прямой промпт ограничен окном контекста выбранной модели; конкретные пределы приведены в официальных карточках [Gemini](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash), [Qwen](https://huggingface.co/Qwen/Qwen3.5-27B) и [GigaChat](https://developers.sber.ru/docs/ru/gigachat/models/updates). Поэтому документ, который после извлечения превышает лимит модели, нельзя целиком передать одним запросом. Осознанно принимаем этот технический долг для сценария одной лабораторной работы. При выходе за лимит или провале критериев качества потребуется чанкинг или RAG; это отдельная задача следующих лабораторных.
