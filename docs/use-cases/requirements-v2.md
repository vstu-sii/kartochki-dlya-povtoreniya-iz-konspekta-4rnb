# Требования v2 после встречи с прототипом

Изменения относительно `docs/use-cases/README.md` отмечены явно.

## Изменено

- **UC-01:** Telegram принимает один PDF с текстовым слоем до 10 МБ; браузерная форма остаётся демонстрационным вводом извлечённого текста. Скан без текстового слоя получает ошибку `PDF_HAS_NO_TEXT_LAYER`, OCR не входит в MVP.
- **UC-01:** при недостатке независимых тезисов набор может содержать меньше пяти карточек вместо повторения одной формулировки. UI объясняет причину.
- **UC-02:** короткий ответ нельзя считать неверным только из-за малого лексического пересечения; verdict `incorrect` требует подтверждённого противоречия или отсутствия ключевого тезиса.
- **UC-02:** feedback обязательно показывает, какой пункт эталона отсутствует, но не раскрывает весь эталон до завершения попытки.
- **UC-03:** повторная оценка атомарно заменяет текущее значение пары session/card. История изменений — аналитическое расширение после MVP.
- **UC-04:** resume открывает первую непройденную карточку после перезапуска Web/Telegram. Автоматическое удаление через 30 дней — задача следующего спринта.
- **UC-05:** prompt injection в материале не исполняется; карточка всё равно обязана иметь дословную цитату из страницы.

## Не изменено

Лимиты 40 страниц / 60 000 оценочных токенов, 5–10 карточек, p95 генерации 60 секунд, p95 review 7 секунд и запрет на чужие сведения остаются критериями целевого MVP. Лимит файла уточнён с 20 до 10 МБ, чтобы совпадать с реализованной защитой API и Telegram-адаптера.
