## Отдельный автоматический E2E-прогон (команда Delivery/Quality)

Технические доказательства: [публичный health](https://kartochki-dlya-povtoreniya-iz-konspekta.onrender.com/health), [E2E smoke](https://github.com/vstu-sii/kartochki-dlya-povtoreniya-iz-konspekta-4rnb/blob/lab3-delivery-prototype/tests/e2e_compose.py), [CI Delivery](https://github.com/vstu-sii/kartochki-dlya-povtoreniya-iz-konspekta-4rnb/actions/workflows/ci.yml?query=branch%3Alab3-delivery-prototype), [verification-2026-10-15.md](../quality/verification-2026-10-15.md).

1. Открыт Web UI / gateway.
2. Вставлен учебный фрагмент про кэш.
3. Создан набор карточек с ожиданием и grounding.
4. Дан текстовый ответ → структурированный verdict.
5. Оценка карточки изменена дважды → в БД актуальная оценка + события истории.
6. Позиция сессии сохранена и восстановлена после повторного открытия.
7. В БД есть `documents`, `card_sets`, `cards`, `answer_reviews`/`answer_attempts`, `study_sessions`, `card_ratings`.
8. В трассировке найдены trace генерации и trace проверки ответа.
9. Guards: не-PDF / oversized / empty → управляемые ошибки без вызова модели.

Автоматика не заменяет ручной проход Постернака Дениса; оба слоя вместе закрывают DoD Lab 3.

## Что удивило

- Даже при 100% grounding качество вопроса нужно оценивать отдельно: схема зелёная, а формулировка может быть обрывком предложения (AI-MANUAL-01).
- Deterministic fallback хуже понимает свободный пересказ; основной Gemini-review оценивает смысл, но без сохранённого измерительного прогона его цифры не заявляются.
- OCR снимает прежний блокер читаемых сканов, но качество зависит от читаемости страницы; рукопись по-прежнему вне MVP.
