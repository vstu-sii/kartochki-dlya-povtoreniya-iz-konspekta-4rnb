# Use cases MVP (v3)

Use cases описывают MVP глазами студента технического вуза, который готовится к устной защите одной лабораторной.

**Актуализация лабораторной 4:** дельты production-итерации — `requirements-v3.md`. PRD и North Star — `../prd.md`. Скоуп — `../mvp-scope.md`. История Lab 3: `requirements-v2.md`, `validation-lab3.md`. Диаграмма: `use-cases.puml`.

## UC-01 — Создать карточки из PDF

**Актёр:** студент.  
**Цель:** за одну минуту получить вопросы по своей методичке.  
**Контекст:** PDF до **10 МБ**, ≤40 страниц, ≤60 000 оценочных токенов; текстовый слой или читаемый печатный скан (базовый OCR).  
**Предусловия:** бот доступен; суточный бюджет пользователя не исчерпан.

**Основной сценарий:**

1. Студент начинает новую подготовку и загружает один PDF.
2. Система до модели проверяет MIME, размер, страницы, injection и суточный бюджет.
3. Извлекается текст (слой или OCR читаемого скана); строится page map.
4. Генерируется набор карточек (цель 5–10; при нехватке тезисов — меньше без дублей).
5. Каждая карточка проходит schema и grounding (страница + дословная цитата).
6. Повтор с тем же idempotency key возвращает прежний результат без списания бюджета.
7. После 80% суточного бюджета используется дешёвая модель; факт модели виден пользователю/telemetry.

**Результат:** набор grounded-карточек готов к повторению.  
**Как поймём:** schema/grounding 100% на golden; генерация ≤60 с; полезность ≥80%.

**Исключения:** не-PDF / >10 МБ / нечитаемый после OCR / шифр / лимит — стабильная ошибка без вызова модели; рукопись вне MVP.

## UC-02 — Пройти раунд вопрос–ответ

**Актёр:** студент.  
**Цель:** проверить ответ своими словами.  
**Предусловия:** есть непройденная карточка.

**Основной сценарий:**

1. Бот показывает вопрос без эталона.
2. Студент отвечает текстом ≤2 000 символов.
3. Система берёт каноническую карточку **только из БД** (клиент не подменяет эталон).
4. Модель возвращает verdict, feedback и missing points.
5. Студент переходит к следующему вопросу.

**Результат:** attempt сохранён, прогресс обновлён.  
**Как поймём:** p95 review ≤7 с (модельный); agreement ≥85% на golden.

**Исключения:** пустой/слишком длинный ответ; `incorrect` только при противоречии или отсутствии ключевого тезиса; «Не знаю» → `skipped` без модели.

## UC-03 — Оценить полезность карточки

**Актёр:** студент.  
**Цель:** отметить, помогает ли вопрос готовиться.

**Основной сценарий:**

1. Бот предлагает «Полезно» / «Не полезно».
2. Авторизованный endpoint приложения сохраняет оценку и событие истории.
3. Модель **не** записывает рейтинг и не завершает сессию.

**Результат:** одна актуальная оценка на пару session/card + история событий.  
**Как поймём:** повторная оценка заменяет значение; в БД видны события.

## UC-04 — Завершить и возобновить сессию

**Актёр:** студент.  
**Цель:** увидеть итог и продолжить позже.

**Основной сценарий:**

1. По завершении показывается сводка verdict.
2. Позиция сохраняется в БД.
3. `/start` или «Продолжить» открывает первую непройденную карточку.
4. Доступ проверяется по владельцу; сессия >30 дней → 410; чужая → 403.

**Результат:** прогресс не теряется у владельца.  
**Как поймём:** resume после рестарта; IDOR закрыт тестами.

## UC-05 — Безопасно отклонить неподдерживаемый документ

**Актёр:** студент.  
**Цель:** понятный отказ вместо плохих карточек.

**Основной сценарий:**

1. Guards проверяют тип, размер, читаемость и injection до модели.
2. Текст PDF — недоверенные данные, инструкции из него не исполняются.
3. Бот показывает стабильный код/сообщение и следующий шаг.

**Результат:** модель не получает недопустимый ввод.  
**Как поймём:** security-набор и HTTP-регрессии зелёные.

## UC-06 — Достичь суточного лимита

**Актёр:** студент.  
**Цель:** понять границу бюджета, не «сломать» сессию.

**Основной сценарий:**

1. При 80% бюджета gateway переключает на дешёвую модель.
2. При 100% запрос отклоняется понятным сообщением.
3. Срабатывание видно в логах, `/metrics` и Grafana.

**Результат:** аномальный расход остановлен кодом, не промптом.  
**Как поймём:** `tests` лимитов + алерт на дашборде.

## UC-07 — Недоступен model tool

**Актёр:** система / студент.  
**Цель:** пережить таймаут инструмента без утечки данных.

**Основной сценарий:**

1. Модель вызывает инструмент по контракту.
2. При таймауте/отказе приложение выбирает безопасный fallback или контролируемую ошибку.
3. Права инструмента минимальны и проверяются кодом.

**Результат:** нет зависания и нет раскрытия секретов.  
**Как поймём:** `tests/test_lab4_tool.py` и контракт в `ml/tools/`.
